propagate
Claude Code plugin · Node, ESM
  • Sole-authored: 218 commits over six weeks, 313 source files, 142 tests — github.com/Rupali59/propagate. Declares the couplings between files that must change together and derives drift from file content on demand rather than storing state, currently watching ~920 edges across 14 workspaces. Installed at user level, so its hooks execute in every agent session on the machine rather than only where it is checked out. A companion marketplace serves 18 skills across 3 plugins.
  • A PreToolUse hook pattern-matches the literal command an agent is about to execute against declared hazards and surfaces the matching one before it runs; written after a documented hazard sitting three files away was hit anyway and cost 11 false verification records. A companion SessionStart hook maintains 18 canonical engineering rules, and a restatement detector tracks them across 50 CLAUDE.md files — it counts a file that restates a rule even where the file also references it, because a pointer beside a stale copy is what a half-finished migration looks like.
  • The rule detectors and both pattern-matching guardrails each ship a selftest that runs each trigger against a known-positive and asserts it fires, plus negative cases it must not match, because a check that cannot fail reports success; it caught a rule whose detector could never have matched its own body. A Claude Cowork job-classification skill is tested against captured fixtures.
  • No downstream file is ever edited automatically — the tooling finds and explains, a person approves, and each decision is recorded as a ledger event. The design principle throughout is that “found nothing” and “looked at nothing” must be different outputs — a probe that cannot report its own failure reports success. Auditing my own monitor against that standard found it logging a hardcoded success field while 49 crashes sat in a stderr log nothing read; the logger could not express the state it was being cited to prove.
